# Эксплуатация доставки событий через JetStream

PostgreSQL остаётся источником истины для событий. JetStream — только
опциональный транспорт с доставкой как минимум один раз; восстановление через
`GET /v1/events` читает PostgreSQL и никогда скрыто не переключается на брокер.

Включайте outbox-worker только после административного создания
`MERCHANT_EVENTS_V1` с фиксированным subject `merchant.events.v1`: минимум три
реплики, конечные лимиты возраста/байтов/сообщений/конверта 1 МиБ, discard-old,
окно дедупликации не меньше максимального повтора, запрет Delete/Purge. Tenant
ID запрещены в subject.

Worker принимает только `tls://` с TLS 1.3, закреплёнными CA и именем сервера,
клиентским сертификатом и ровно одним смонтированным файлом credentials или
token. Порт 4222 и health остаются приватными. Readiness проверяет PostgreSQL,
NATS и точную политику stream. При сбое оставляйте строки ожидающими и не
меняйте транспорт. Published отмечается только после ack правильного stream с
ненулевой sequence; повтор сохраняет `Nats-Msg-Id=event_id`.

Эталонный pull-consumer подтверждает сообщение только после атомарного commit
inbox и бизнес-эффекта; дубликат считается успехом. Перед релизом нужны живые
доказательства ошибок TLS, drift политики, потерянного ack, backpressure, сбоя
БД после ack и redelivery. Локальные тесты не доказывают работу живого кластера.
