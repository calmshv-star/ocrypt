# Эксплуатация rate runtime

Rate worker — fail-closed data plane. Он читает только активные immutable snapshots `rate_policy` и `rate_source` через `ActiveSnapshotReader`; draft/approved/scheduled версии не используются. Перед атомарной записью worker повторно проверяет snapshot ID и fence token под блокировкой, поэтому конкурентная активация откатывает весь сбор.

Policy задаёт `base_asset`, `quote_asset`, минимум два различных `sources`, `quorum`, `max_age_seconds`, `max_spread_bps`, опциональные `future_tolerance_seconds` (по умолчанию 5, явный 0 означает строгий ноль) и `poll_interval_seconds` (15). Source задаёт `provider_ref`, нормализованный HTTPS `endpoint`, ту же пару, `max_age_seconds`, опциональные `timeout_ms`, `max_response_bytes` и `credential_ref`. Endpoint не может содержать credentials, query или fragment.

Ответ провайдера описан `contracts/rate-provider-v1.schema.json`: цена означает количество единиц котируемой фиатной валюты за одну целую базовую монету и передаётся только положительными uint256 numerator/denominator, без JSON number и float. Планировщик считает `fiat / price` с точными масштабами валюты и актива и округляет атомарную сумму вверх. Проверяются пара, свежесть, будущая дата, quorum различных источников и точный spread. При чётном числе источников консервативно выбирается нижняя реально наблюдавшаяся медиана — без усреднения. При отсутствующей конфигурации, stale/future данных, недостаточном quorum или divergence tick не создаётся.

Redirect/proxy и private, loopback, link-local, reserved либо смешанные DNS-ответы блокируются; DNS закрепляется на соединение. TLS, timeout, content type и размер ответа ограничены. `credential_ref` читается только из read-only `RATE_SECRET_DIR`; path/symlink escape и многострочные secrets запрещены. Secrets не попадают в snapshots, БД, логи, health или merchant credentials.

Standalone bootstrap создаёт политики `RUB`, `USD`, `EUR`, `KZT`, `INR` и `CNY`, но supplied worker по умолчанию включает только 26 RUB targets. Остальные валюты не создают фоновых или внешних запросов, пока deployment явно не добавит соответствующие ключи в `RATE_TARGETS_JSON`. Успешная пара обновляется раз в 30 минут. При создании счёта tick в пределах разрешённого срока свежести используется сразу; только отсутствующая или устаревшая пара ставит одну дедуплицированную задачу вне очереди. Встроенный нормализующий gateway пакетирует и кеширует внешние запросы. Используются три независимых источника: CoinGecko, CoinPaprika и CoinMarketCap. Достаточно любых двух свежих согласованных курсов. Недоступный источник исключается; при расхождении выбирается наиболее близкая группа, обеспечивающая quorum. Повторяющийся `provider_ref` в одной политике запрещён. CoinMarketCap по умолчанию использует публичный API без ключа, стабильные ID монет и исходное время обновления актива/котировки; ключ опционально переключает на keyed API. Для KZT у CoinGecko/CoinPaprika применяется официальный USD/KZT Национального банка Казахстана, а CoinMarketCap котирует KZT напрямую. `rate_gateway_origin` обязателен при standalone bootstrap и должен быть внешним HTTPS origin API. Порядок активации и проверок описан в [runbook восстановления курсов](../../deploy/standalone/rate-provider-recovery.md).

Обязательные env: `DATABASE_URL`, UUID `RATE_WORKER_ID`, строгий глобальный `RATE_TARGETS_JSON`. Tenant target запрещён, пока planner использует глобальную пару; `base_asset` обязан совпадать с active `assets.id`, `quote_asset` — трёхбуквенный fiat. Опциональные: `RATE_SECRET_DIR`, `RATE_POLL_INTERVAL=1s` (только одна дешёвая проверка очереди, не внешний запрос), `RATE_LEASE_DURATION=30s`, `RATE_MAX_ATTEMPTS=8`, `RATE_MAX_READY_AGE=35m`, `RATE_HEALTH_ADDRESS=:9092`. До миграции 000007 создайте NOLOGIN role `rate_runtime_worker` (либо выдайте conditional grants после), workload login наследует её; enabled identity с тем же UUID создаёт operations owner.

`/healthz` проверяет БД. `/readyz` готов только если у каждой цели есть свежий непросроченный tick и нет dead-letter. Lease fenced; ошибки получают exponential backoff. При достижении лимита временные ошибки источников, свежести и quorum сбрасывают счётчик с паузой минимум 5 минут и продолжают повторные попытки: временный сбой не выключает валюту навсегда. Неповторяемые ошибки создают immutable dead-letter. Успешная serializable transaction сохраняет immutable admission/provenance и атомарно проецирует тот же tick в старую `asset_rate_ticks`, которую реально читает `PersistedPlanner`, supersede предыдущий active. Unique pair index и стабильный policy binding исключают неоднозначность; недостаточный согласованный quorum не становится selectable.
