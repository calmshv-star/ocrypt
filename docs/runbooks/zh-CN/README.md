# 运维手册

这些流程适用于生产和预发布环境。发生事件时，先执行“重大事件”中的通用
控制，再进入对应场景。任何人取得生产数据库恢复权限前，都必须完成恢复演练。

- [重大事件](critical-incidents.md)：服务中断、扫描器分歧、链重组、回调故障、
  未匹配付款激增及凭据泄露。
- [备份与恢复](backup-restore.md)：备份控制、隔离恢复、对账和切换。
- 发布与回滚的规范流程见英文目录。

扫描器当前默认关闭，因为其二进制和提供商集成尚未完成生产准入。Deployment
存在或健康检查通过，都不代表可以启用自动入账。上线至少需要：签名且不可变
的镜像摘要、外部 Secret、独立数据库角色、已执行的 NetworkPolicy、PostgreSQL
TLS、验证过的 PITR 和恢复演练、值班责任人以及测试过的告警。当前应用还没有
原生财务/队列指标，仅靠健康检查不满足上线条件。
