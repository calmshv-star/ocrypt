# Руководства оператора

Все процедуры применимы к production и staging. При инциденте сначала выполните
общие меры из руководства по критическим инцидентам, затем перейдите к нужному
сценарию. Доступ к восстановлению production-БД разрешается только после изучения
и практической проверки процедуры восстановления.

- [Критические инциденты](critical-incidents.md): недоступность, расхождение
  сканеров, реорганизация сети, callback, неопознанные платежи и утечка ключей.
- [Резервное копирование и восстановление](backup-restore.md): контроль копий,
  изолированное восстановление, сверка и переключение.
- Канонические процедуры релиза и отката находятся в английском разделе.

Сканер сейчас выключен по умолчанию: production-допуск его бинарника и интеграций
ещё не завершён. Наличие deployment или успешная health-проверка не являются разрешением на автоматический приём
транзакций. До запуска обязательны подписанные digest образов, внешние Secret,
раздельные роли БД, NetworkPolicy, TLS к PostgreSQL, проверенный PITR, учебное
восстановление, дежурная команда и проверенные тревоги. Одних health-проверок
недостаточно: нативные финансовые и очередные метрики ещё не реализованы.
