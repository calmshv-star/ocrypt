# Переход сервиса на единый webhook-протокол

Ocrypt использует один протокол для всех сервисов. Команды создания и чтения
заказа отправляются в Merchant API с отдельной HMAC-учётной записью. Изменения
состояния приходят только как подписанные webhook-события. Периодический опрос
не является штатным каналом и допускается лишь как временный recovery-механизм
на время перехода.

## Что настраивается в подключаемом сервисе

- `MERCHANT_BASE_URL` — публичный origin Ocrypt без дополнительного пути;
- `MERCHANT_KEY_ID` и `MERCHANT_SECRET` — отдельная HMAC-пара с минимальными
  правами `payments:read` и `payments:write`;
- публичный `OCRYPT_WEBHOOK_MERCHANT_ID`;
- `OCRYPT_WEBHOOK_SECRETS_FILE` — путь к read-only JSON keyring вне `.env`;
- HTTPS endpoint `/ocrypt/webhook/`, который принимает challenge и события.

Webhook-получатель обязан до JSON-декодирования проверить digest, timestamp,
event ID, key ID, HMAC исходного тела, merchant ID, environment и допустимый
event type. В одной транзакции он фиксирует `(event_id, body_digest)`, меняет
заказ и создаёт задание на выдачу услуги. Повтор с тем же ID и digest безопасно
подтверждается; тот же ID с другим digest считается инцидентом. Ответ содержит
точный ID события. Выдача выполняется только для `payment.settled` и остаётся
идемпотентной по заказу.

## Безопасный порядок включения

1. Сохранить текущую версию сервиса и его базы для отката.
2. Развернуть endpoint и durable inbox, не отключая recovery polling.
3. Добавить endpoint в Ocrypt и успешно пройти challenge.
4. Запустить callback worker и отправить контролируемое событие.
5. Убедиться, что доставка `acknowledged`, inbox содержит одну запись, а
   повторная доставка не повторяет бизнес-эффект.
6. Проверить timeout, неверную подпись, устаревшее время, неизвестный key ID,
   повтор, конфликт digest и очередь retry/dead-letter.
7. Только после этого отключить штатный polling. Event API оставить лишь для
   ручного восстановления разрыва по sequence.

Если endpoint недоступен или проверка не закончена, callback worker не включают,
а старый способ работы не удаляют. Секреты не передают через чат, Git, `.env`,
аргументы процесса или логи.
